Учебный проект курса «Специалист по Data Science» (Яндекс Практикум), спринт «Машинное обучение для текстов».

Интернет-магазин «Викишоп» запускает сервис, где пользователи сами редактируют описания товаров и комментируют чужие правки. Магазину нужен инструмент, который находит токсичные комментарии и отправляет их на модерацию.

| | |
|---|---|
| **Задача** | бинарная классификация текста (токсичный / нетоксичный) |
| **Целевая метрика** | F1 >= 0.75 по классу «токсичный» |
| **Достигнуто** | **F1 = 0.834** на отложенной тестовой выборке |
| **Лучшая модель** | дообученный DistilBERT, порог 0.613 |

---

## Данные

[`toxic_comments.csv`](https://code.s3.yandex.net/datasets/toxic_comments.csv) - 159 292 размеченных комментария из англоязычной Википедии.

- `text` - текст комментария
- `toxic` - целевой признак (0 / 1)

Пропусков и дубликатов нет. Классы несбалансированы: токсичных **10.2%** (16 186 из 159 292). Медианная длина комментария - 36 слов, распределение сильно скошено вправо (максимум 1411 слов).

Файл весит 62 МБ и в репозиторий не входит - скачивается отдельно, см. [Воспроизведение](#воспроизведение).

## Подход

**Подвыборка.** Для обучения взяты стратифицированные 50 000 комментариев, разбитые на обучающую / валидационную / тестовую части в соотношении 60/20/20 (30 000 / 10 000 / 10 000). Полный датасет потребовал бы нескольких часов на дообучение BERT-base на одной видеокарте, а качество предобученного трансформера от сокращения выборки втрое страдает слабо.

**Единый протокол сравнения.** Все модели обучаются на одних и тех же данных. Гиперпараметры и порог классификации подбираются на валидации, тестовая выборка используется ровно один раз - для финальной проверки лучшей модели. Отдельная валидационная выборка вместо кросс-валидации выбрана намеренно: полноценная кросс-валидация для BERT потребовала бы кратно больше времени на GPU, а сравнивать модели нужно по одному протоколу.

**Два представления текста.**

- Для моделей на мешке слов - очистка (только латинские буквы и апостроф, нижний регистр) и лемматизация `WordNetLemmatizer` с учётом частей речи. Без POS-тега лемматизатор WordNet считает любое слово существительным и не сводит `hated` к `hate`.
- Для BERT - исходный текст без изменений: у трансформера собственный подсловный токенизатор, а пунктуация и структура предложения входят в контекст, на который он опирается.

**Длина последовательности.** `max_length = 192` выбрана по распределению длин в токенах: целиком помещается 89% комментариев, при 256 - 93%, но обучение дорожает примерно на треть. Обрезка не критична, токсичность обычно проявляется в первых же фразах.

**Дисбаланс классов** компенсируется двумя способами: `class_weight="balanced"` у линейных моделей и подбор порога классификации по кривой «точность - полнота» для всех моделей без исключения.

## Выводы

**1. BERT здесь нужен по делу, а не для галочки.** Лучшая модель на мешке слов дала на тесте 0.7470 - то есть **не дотянула** до требуемых 0.75, хотя на валидации проходила (0.7503). Классические подходы к этой задаче применимы только как быстрый ориентир.

**2. Выигрыш трансформера - в полноте.** TF-IDF опирается на обсценную лексику и ловит две трети токсичных комментариев (recall 0.67). BERT учитывает контекст и находит 80%, не теряя в точности.

**3. Дистиллированная модель предпочтительнее полной.** BERT-base не дал прироста относительно DistilBERT (0.8313 против 0.8315), но обучался в 2.3 раза дольше и требует вдвое больше памяти. Для продакшена это вдвое меньший счёт за инференс при том же качестве.

**4. Бустинг проиграл линейным моделям.** LightGBM на TF-IDF показал 0.7168, обучаясь в 50 раз дольше логистической регрессии. Ожидаемо: решающие деревья плохо работают с очень разреженными высокоразмерными признаками, где каждое разбиение опирается на одно слово.

**5. Качество упирается в разметку.** Разбор ошибок показал, что все три самых уверенных «ложных срабатывания» - комментарии с прямыми оскорблениями, помеченные в датасете как нетоксичные. Это ошибки разметки, а не модели: реальная точность выше измеренной. Модель же действительно пропускает завуалированную агрессию без обсценной лексики - пренебрежительный тон, переход на личности, претензии капслоком.

## Использование обученной модели

Ноутбук сохраняет победившую модель в `models/toxic_classifier` - веса, токенизатор и `inference.json` с порогом классификации. Порог принципиален: без него модель откатится к 0.5 и потеряет часть качества.

```python
import json
import torch
from transformers import AutoModelForSequenceClassification, AutoTokenizer

MODEL_DIR = "models/toxic_classifier"
config = json.load(open(f"{MODEL_DIR}/inference.json"))

tokenizer = AutoTokenizer.from_pretrained(MODEL_DIR)
model = AutoModelForSequenceClassification.from_pretrained(MODEL_DIR).eval()


def is_toxic(text):
    batch = tokenizer(text, truncation=True, max_length=config["max_length"], return_tensors="pt")
    with torch.no_grad():
        proba = torch.softmax(model(**batch).logits, dim=1)[0, 1].item()
    return proba >= config["threshold"], round(proba, 3)


print(is_toxic("thanks for the fix, looks good now"))   # (False, 0.001)
print(is_toxic("you are an idiot and your edits are garbage"))  # (True, 0.997)
```

## Ограничения и что можно улучшить

Это учебный проект, а не продакшен-решение. Осознанные упрощения и направления развития:

- **Обучение на подвыборке 50k вместо полных 159k.** Компромисс ради времени прогона. На полном датасете метрика вырастет, но выводы о сравнении моделей не изменятся.
- **Одна конфигурация вместо ансамбля.** Усреднение нескольких запусков с разными зёрнами обычно добавляет 0.005-0.01 F1.
- **Контекст 192 токена.** У 11% комментариев хвост обрезается.
- **Не пробовались специализированные чекпоинты** - `RoBERTa` или модели, предобученные на комментариях соцсетей.
- **Порог 0.613 максимизирует F1**, но в реальном сервисе его стоит выбирать из стоимости ошибок: понижение увеличит полноту ценой роста нагрузки на модерацию.
- **Модель не должна банить автоматически.** С полнотой 0.80 и неидеальной разметкой её место - приоритизатор очереди на модерацию, а не окончательный судья.

## Чему научился

- Дообучать трансформер с нуля на PyTorch, без обёрток: планировщик learning rate, смешанная точность, отбор лучшей эпохи по метрике на валидации.
- Строить честный протокол сравнения разнородных моделей - от константной до BERT - на едином разбиении данных.
- Работать с несбалансированными классами: почему accuracy бесполезна, чем `class_weight` отличается от подбора порога и почему порог надо подбирать на валидации, а не на тесте.
- Читать ошибки модели, а не только метрики: разбор ложных срабатываний вскрыл ошибки в самой разметке датасета.
- Соотносить стоимость и выигрыш: BERT-base оказался вдвое дороже DistilBERT при том же качестве.
